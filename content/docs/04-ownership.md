# 04. 所有権: Rust 最大の特徴

## 🎯 この章のゴール

- 所有権の 3 ルールを言えるようになる
- **ムーブ**・**クローン**・**コピー** の違いを理解する

## 💡 ひとことで言うと

> 値は **一冊の本**、変数は **持ち主**。本を誰かに渡したら、自分の手元にはもうありません。持ち主が部屋（スコープ）を出るとき、本は片付けられます。

## なぜ所有権？

メモリ管理の方式はだいたい 2 つでした。

- **手動管理（C/C++）**: 速いが、解放忘れ・二重解放のバグが起きやすい
- **GC（Java, Go など）**: 安全だが、実行時のコストがかかる

Rust はどちらとも違い、コンパイル時に所有権ルールをチェックすることで、GC なしで安全性を保証します。

## 3 つのルール

1. 各値には **所有者** と呼ばれる変数がある
2. 所有者は **同時に 1 つだけ**
3. 所有者がスコープを抜けると、値は **破棄（drop）** される

```rust
fn main() {
    {
        let s = String::from("hello"); // s が所有者
        println!("{s}");
    } // ← ここで s がスコープを抜け、メモリが解放される
}
```

## ムーブ: 所有権の移動

```rust {class="compile-fail"}
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;          // 所有権が s2 へムーブ
    println!("{s1}");     // error[E0382]: borrow of moved value: `s1`
}
```

`String` はヒープ上にデータを持ちます。もし `s1` と `s2` の両方が同じデータを所有したら、スコープ終了時に **二重解放** が起きてしまいます。だから Rust は `s1` を無効にするのです。

```text
 スタック            ヒープ
 s1 (無効) ─┐
            ├──▶ [h][e][l][l][o]
 s2 ────────┘
```

## クローン: 明示的な複製

ヒープのデータごと複製したいときは `clone()` を呼びます。重い複製は必ず `clone()` と書くことになるので、どこでコストがかかるかがコードを読めば分かります。

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();
    println!("{s1} {s2}"); // どちらも使える
}
```

## コピー: スタックだけの型

整数・浮動小数点・`bool`・`char`、それらだけからなるタプルなどは `Copy` トレイトを持ち、代入しても元の変数が使えます。

```rust
fn main() {
    let x = 5;
    let y = x; // コピー
    println!("{x} {y}");
}
```

## 関数と所有権

関数に渡す・関数から返すのも、ムーブ（またはコピー）です。

```rust
fn take(s: String) {
    println!("{s}");
} // s はここで drop

fn give() -> String {
    String::from("gift") // 所有権を呼び出し元へ返す
}

fn main() {
    let a = String::from("hi");
    take(a);            // a はムーブ済み。以降 a は使えない
    let b = give();     // b が新しい所有者
    println!("{b}");
}
```

毎回所有権を渡して返してもらうのは面倒ですよね。そこで登場するのが次章の **参照（借用）** です。

## 📝 まとめ

- 値の所有者は常に 1 つ。スコープを抜けると自動で解放
- ヒープを持つ型（`String`, `Vec` など）は代入・関数渡しで **ムーブ**
- 複製したいなら `clone()`、`Copy` 型は自動でコピー
